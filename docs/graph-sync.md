# 🕸️ Knowledge Graph & Sync (Obsidian ⇄ Graphify)

> How this vault's documentation graph stays in sync across **Obsidian Graph View** and **Graphify** — and how to keep it that way.

## The Two Graphs

| System | Where it lives | What it graphs | How it's built |
|---|---|---|---|
| **Obsidian Graph** | Built into Obsidian (Graph view) | All `.md` notes + wiki-links | Automatic — Obsidian parses links live |
| **Graphify** | `.graphify/graph.json` | Docs as nodes, wiki-links as edges | Generated by `scripts/sync-graphify.py` |

**Single source of truth = the markdown files' wiki-links.** Both graphs are *derived* from the same links, so they can never semantically disagree — they just need re-derivation when files change.

## Keeping Them in Sync (the contract)

Run after **adding, renaming, or deleting** any `.md` file, or after changing links:

```bash
python scripts/sync-graphify.py
```

The script:
1. Scans all `*.md` in the vault (excluding `.obsidian/`, `.graphify/`, `node_modules/`)
2. Parses wiki-links (including `[[path|alias]]` and `[[doc#section]]` forms)
3. Emits `.graphify/graph.json` in graphify's node/link format (nodes carry `file_type: "doc"`, `community` by folder)
4. Updates `.graphify/manifest.json` with file mtimes + hashes (same shape graphify itself uses) so graphify sees a consistent workspace
5. Prints a summary: nodes, links, orphaned docs, broken links

### Communities (auto-assigned by folder)
| Folder | Community | Color hint |
|---|---|---|
| `/` (root) | Core documents | blue |
| `docs/` | Deep-dive docs | green |
| `tasks/` | Working notes | orange |
| `canvas/` | Visual maps | purple |

## Obsidian Side Configuration

Already enabled in this vault (`.obsidian/core-plugins.json`): `graph`, `canvas`, `backlink`, `outgoing-link`. Recommended Graph view filters:

- **Local graph on `CLAUDE.md`** → shows the whole doc constellation (it's the hub)
- **Graph → Groups** → color by folder path to mirror graphify communities

## Canvas Files

Canvases (`canvas/*.canvas`) are Obsidian-native JSON visual maps. They reference notes by relative path, so **renaming a note breaks canvas nodes** — if you rename a doc, update the canvas or re-run the sync script (it warns on missing canvas references).

## Rules for Humans & Agents

1. **Link generously** — every doc should link to at least 2 others; orphans get flagged by the sync script
2. **Use wiki-links, not raw paths** — they survive renames inside Obsidian and feed both graphs
3. **After structural changes → run the sync script** → commit `.graphify/` changes with the doc changes (one commit = consistent graph)
4. **Never hand-edit `.graphify/graph.json`** — regenerate it instead
